# pi-extensions

Personal collection of extensions for Pi Agent.

## Packages

| Package | Description |
|---------|-------------|
| [`pi-agent-introspection`](packages/pi-agent-introspection) | Registers two self-introspection tools: `get_session_debug_info` (session metadata, token usage, context entries, full system prompt) and `inspect_commands` (all registered slash commands with descriptions). Both inactive at `session_start`; activate via `manage_tools`. |
| [`pi-ask-user-question`](packages/pi-ask-user-question) | Registers an `ask_user_question` tool so the LLM can open a tabbed TUI dialog for structured clarifying questions (single/multi-select, optional previews, free-text fallback). |
| [`pi-aws-ec2-watcher`](packages/pi-aws-ec2-watcher) | Watches AWS EC2 instances by ID for state transitions and injects one chat notification per change. Registered at `session_start` but inactive — activate with `manage_tools({"action":"activate","tools":["ec2_watcher"]})`. The `/ec2-watcher` slash command opens a TUI (browse / pause / resume / start / stop). |
| [`pi-aws-glue-watcher`](packages/pi-aws-glue-watcher) | Watches AWS Glue job and workflow runs for state changes and injects one chat notification per change. Registered at session_start but inactive — LLM activates via `manage_tools({action:"activate",tools:["glue_watcher"]})`. The `/glue-watcher` slash command opens a TUI menu (browse watches, pause/resume, display-mode switches) for user-side control. Polls `GetJobRun`/`GetWorkflowRun` on a 60 s → 15 min back-off; self-terminates on SUCCEEDED/FAILED/STOPPED/TIMEOUT/ERROR. |
| [`pi-aws-s3-watcher`](packages/pi-aws-s3-watcher) | Watches a single AWS S3 object URI for existence, update, or removal via the AWS SDK. Fires exactly one chat notification when the target condition is met (or when the 72 h max watch duration elapses). Polls on a back-off schedule (60 s base, doubles to a 15 min cap; resets on any observable change). Registered at `session_start` but inactive by default — activate with `manage_tools({"action":"activate","tools":["s3_watcher"]})` via `pi-tools-management-tool`. |
| [`pi-browser-control`](packages/pi-browser-control) | Registers the `browser_list_tabs` read-only tool that talks to Firefox via a bundled WebExtension and a shared Node native-messaging daemon. Firefox spawns and owns one daemon per machine; every pi session connects to it over a unix socket (`~/.pi/agent/pi-browser-control.sock`), so concurrent sessions never contend for a port. Load the add-on from `packages/pi-browser-control/firefox-addon`, run `scripts/install.ts` (or `/browser-control` → Install) to write the native-messaging manifest + launcher, then use `/browser-control` → Test connection. (`browser_get_tab_content` is implemented but disabled by default — `executeScript` can hang on streaming/SPA tabs; opt in via `enableGetTabContent`.) |
| [`pi-btw`](packages/pi-btw) | Copy of [`dbachelder/pi-btw`](https://github.com/dbachelder/pi-btw) (MIT, © Dan Bachelder): adds a `/btw` side-conversation channel that opens a real pi sub-session with full tool access in a dedicated overlay, so you can ask questions or explore ideas in parallel without polluting the main thread. Supports `/btw:tangent`, `/btw:inject`, `/btw:summarize`, and BTW-only model/thinking overrides. |
| [`pi-built-in-tool-renderer`](packages/pi-built-in-tool-renderer) | Copy of [`badlogic/pi-mono/examples/built-in-tool-renderer.ts`](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/examples/extensions/built-in-tool-renderer.ts) (MIT, © Mario Zechner): re-registers the built-in `read` / `bash` / `edit` / `write` / `find` / `grep` / `ls` tools with compact custom renderers while delegating execution to the originals. |
| [`pi-claude-code-commands-import`](packages/pi-claude-code-commands-import) | Imports Claude Code slash commands (`~/.claude/commands` and project-local `.claude/commands`) into pi as prompt templates, making them available as `/command-name` in pi. |
| [`pi-claude-code-skills-import`](packages/pi-claude-code-skills-import) | Imports Claude Code installed skills (user skills, plugin-cache skills, and project-local `.claude/skills`) into pi via `resources_discover`. |
| [`pi-file-system-watcher`](packages/pi-file-system-watcher) | Watches a local filesystem path (file or directory) for existence, change, or removal, polling `fs.stat` on a back-off schedule and injecting one chat notification per state change. The `file_system_watcher` tool is registered at `session_start` but inactive — activate with `manage_tools({"action":"activate","tools":["file_system_watcher"]})`. The `/file-system-watcher` slash command opens a TUI (browse / pause / resume). |
| [`pi-git-watcher`](packages/pi-git-watcher) | Watches a local Git repository for new commits, branch creation/deletion, and tag creation. Continuous — fires repeatedly until removed. Polls local refs only (no `git fetch`); 60 s → 15 min back-off. Activate via `manage_tools({"action":"activate","tools":["git_watcher"]})`. |
| [`pi-goal`](packages/pi-goal) | Codex-style autonomous `/goal` command: set an objective and pi works toward it across turns until the agent calls `goal_complete`, the iteration cap is hit, or the token budget is exhausted. The three lifecycle prompt templates (`continuation.md`, `budget_limit.md`, `objective_updated.md`) are copied verbatim from [openai/codex](https://github.com/openai/codex) (Apache 2.0). No separate checker model. Config: `~/.pi/agent/pi-goal.json` (`maxIterations`, `tokenBudget`). |
| [`pi-herdr-integration`](packages/pi-herdr-integration) | Pi extension that renames the active herdr workspace to the session display name whenever the session name is set or changes. Triggers on session start/restore and intercepts the built-in /name command. No-op outside herdr (HERDR_ENV != "1"). Session state key: pi-herdr-integration:state. |
| [`pi-local-issue-watcher`](packages/pi-local-issue-watcher) | Watches a `local-skill-issues-tracker` database on disk and injects issue change notifications into pi chat as `local-issue-watcher` custom messages. |
| [`pi-plan-mode`](packages/pi-plan-mode) | Based on [`badlogic/pi-mono/examples/plan-mode`](https://github.com/badlogic/pi-mono/tree/main/packages/coding-agent/examples/extensions/plan-mode) (MIT, © Mario Zechner): read-only exploration mode toggled via `/plan`, `Ctrl+Alt+P`, or `Shift+Tab`, with a bash allowlist and a post-plan action prompt (execute / stay / refine). |
| [`pi-prompt-scheduler`](packages/pi-prompt-scheduler) | Local port of [`tintinweb/pi-schedule-prompt`](https://github.com/tintinweb/pi-schedule-prompt) (MIT, © tintinweb), trimmed to an LLM-only surface: registers a `schedule_prompt` tool (cron, interval, relative time, ISO timestamps; optional subagent mode) and a browse/cancel TUI (`/schedule-prompt`). Manual add flow removed — jobs are created exclusively by the agent. Live widget below the editor; persistence via `.pi/schedule-prompts.json`. |
| [`pi-extensions-browser`](packages/pi-extensions-browser) | Registers a `/extensions` command that opens an interactive TUI listing all extension commands registered in the current session, grouped by **project scope** and **user scope**, with name and source path. Type-to-filter search, ↑↓ navigation, Esc to close. |
| [`pi-session-recap`](packages/pi-session-recap) | Port of [`tmustier/pi-extensions/session-recap`](https://github.com/tmustier/pi-extensions/tree/main/session-recap) (MIT, © Thomas Mustier): shows a one-line Claude-Code-style recap above the editor when you refocus a pi session so you can re-enter flow without re-reading scrollback. |
| [`pi-skills-browser`](packages/pi-skills-browser) | Registers a `/skills` command that opens an interactive TUI listing every skill registered in the current session with its name and a description token estimate. Supports filter-as-you-type and toggling sort between alphabetical and token-count descending with `s`. |
| [`pi-speak`](packages/pi-speak) | Registers a `speak` tool that synthesises text via the bundled Supertone TTS engine (ONNX runtime, in-process) and plays it through the OS audio device. Inactive by default every session; `/speak` toggles it on/off. When assets are missing, `/speak` prints the `huggingface-cli download` command to run. Session state stored under the `pi-speak:state` custom type. |
| [`pi-subagents`](packages/pi-subagents) | Copy of [`tintinweb/pi-subagents`](https://github.com/tintinweb/pi-subagents) (MIT, © tintinweb): Claude Code-style autonomous sub-agents for pi. Registers the `Agent`, `get_subagent_result`, and `steer_subagent` tools, along with a `/agents` management command. Supports foreground and background execution, agent types defined via `.pi/agents/*.md` files, smart group notifications, scheduled agents (cron/interval/one-shot), worktree isolation, and a live agent-activity sidebar widget. |
| [`pi-thinking-level-control`](packages/pi-thinking-level-control) | Separate `ctrl+]` / `ctrl+[` shortcuts for stepping thinking level up/down one rung at a time. No-op at the extremes; `xhigh` is clamped to `high` on decrease. |
| [`pi-tools-browser`](packages/pi-tools-browser) | Registers a `/tools` command that lists every tool available in a pi session (builtin / sdk / extension / skill), with per-tool description, parameter schema, active/inactive state, and a compact `chars/4` token estimate. Supports `/tools <name>` to jump directly to a tool and `/tools --all` to dump all at once; press `t` in any view to toggle a tool on/off (persisted to session). |
| [`pi-tools-management-tool`](packages/pi-tools-management-tool) | Registers a model-facing `manage_tools` tool so the LLM itself can list/activate/deactivate/reset the active tool set at runtime via pi's `setActiveTools` API. Changes apply on the next turn. `manage_tools` is self-protected so the LLM cannot lock itself out; `reset` restores the set captured at `session_start`. Complements `pi-tools` (the user-facing `/tools` TUI). |
| [`pi-agent-version`](packages/pi-agent-version) | Registers a `/version` slash command that prints the running `@earendil-works/pi-coding-agent` version to the notification area (e.g. `pi-coding-agent v1.2.3`). Version is resolved at runtime via `import.meta.resolve` + `readFileSync` — no build-time baking. |

## Shared libraries

Workspace packages that are **not** pi extensions — they expose no `registerExtension` default export and are never loaded by pi directly. They exist only to be imported by the extension packages above.

| Package | Description |
|---------|-------------|
| [`pi-watcher-core`](packages/pi-watcher-core) | Shared library consumed by the `*-watcher` extensions. Provides back-off-aware `PollScheduler`, session-log persistence with malformed-entry tolerance, a `makeWatcherErrors` taxonomy factory, a sanitizing error classifier, an aggregated-error formatter, and TUI status-line / message-renderer helpers. Depend on it via the workspace: `"pi-watcher-core": "*"`. Do **not** list this package in a pi install command — it has no extension entry point. |
